# Continuity Ledger

A living document. Update after every chapter, not at the end. Copy this file into the project and keep one authoritative copy.

## How to use

- Give every fact a stable ID (C01, W01, P01...).
- Record the chapter where the fact is established and every later use.
- When new text conflicts, do not silently retcon. Choose one of:
  a) earliest mention wins, and revise the new text;
  b) the new text dramatises a correction (a lie exposed, a record proven false);
  c) deliberate change, logged in the Change Register with a reason.
- If a fact is unknown, write UNKNOWN. Do not guess; an explicit gap is safer than an invented detail.

### Resolution protocol

For each conflict, choose exactly one resolution and execute it fully:

1. **Earliest wins.** Revise the new text. Use when the earlier fact is load-bearing.
2. **Dramatise the correction.** The new text reveals the earlier fact was wrong, lied about, or misrecorded. Requires a scene that shows who was deceived and why.
3. **Retire the old fact.** A character acts so the old fact stops mattering. Requires an on-page cause.

Never offer two mechanisms for one conflict ("either the bridge was closer or the estimate counted wagons"). The first is a story cause; the second is renumbering in costume. Ask: does the fix change what a character can do, or only what the text asserts? If only the text, label it an adjustment and say so.

## Audit procedure

1. Before writing a chapter, read the rows for every character, place, and object it will use.
2. After writing, add new facts and update statuses.
3. Every five chapters, scan for drift: names, numbers, dates, powers, injuries.
4. At each arc boundary, reconcile open promises and the timeline.
5. Before the ending, confirm every open setup has a status: paid or deliberately retired with a scene.
